# Data Format Notes — Synthetic Document Dataset

> **All data in `data/synthetic/` is entirely fictional.**
> No real personal information is used at any point.
> Every image is visually labelled "SYNTHETIC / TEST DATA".
>
> Current statistics: see `DATASET.md` (generated by `scripts/dataset_stats.py`).

> ⚠️ **Read §6 before running the generator.** Some generator modes overwrite the
> original Day 1 payslips or silently duplicate existing documents.

---

## 1. Current dataset layout

```
data/synthetic/
├── index.csv            ← one row per indexed document (75 rows)
├── genuine/             ← 48 genuine documents
├── tampered/            ← 27 tampered documents
├── payslip_001.png  ┐
├── payslip_002.png  │
├── payslip_003.png  │   5 original Day 1 payslips — NOT in index.csv
├── payslip_004.png  │   (do not overwrite; see §5)
└── payslip_005.png  ┘
```

The **indexed dataset** is exactly the 75 documents in `genuine/` and `tampered/`
listed in `index.csv`: 30 payslips, 23 bank statements and 22 ID proofs, numbered
`001`–`075`. The training code and `scripts/dataset_stats.py` read only these two
folders. `tests/test_dataset.py` fails if any file is added to or removed from
`data/synthetic/`, or if an indexed image no longer matches its recorded size and byte
count.

`data/demo/` (Founder A's Day 7 demo set) is separate from this dataset: its images are
copies or derivatives of dataset files and are not indexed or counted (see §5).

`data/generated/dev_v1/` and `data/generated/holdout_v1/` (Founder A, Day 8) are also
separate: 150 and 149 documents produced with this generator through the safe workflow in
§6 (seeds 7001 / 7002, numbered from 1001 / 2001 so names never clash with this dataset),
each with its own `index.csv` (same columns) and a `manifest.json` of SHA-256 hashes.
`dev_v1` is model-v2 training data; `holdout_v1` is evaluation-only. They are created by
`scripts/generate_extra_documents.py`, which refuses to overwrite and drops any near-copy
of an existing image. They are not part of the 75-document index.

Filenames: `payslip_NNN.png`, `bank_stmt_NNN.png`, `id_proof_NNN.png`, where `NNN` is
a number shared across all three types (e.g. `bank_stmt_047.png`).

## 2. `index.csv` columns

| Column | Type | Meaning |
|---|---|---|
| `filename` | str | e.g. `bank_stmt_047.png` |
| `path` | str | Relative to `data/synthetic/`; always `<label>/<filename>` |
| `doc_type` | str | `payslip`, `bank_statement` or `id_proof` |
| `label` | str | `genuine` or `tampered` (matches the folder) |
| `tamper_method` | str | Empty for genuine; one of `blur_region`, `color_shift`, `noise_patch`, `text_overlay` for tampered |
| `width`, `height` | int | Image size in pixels |
| `file_size_bytes` | int | File size on disk |

### Bank statement (`generate_fake_bank_statement()`)

`bank_name`, `bank_branch`, `account_holder`, `account_number` (masked), `ifsc_code`,
`statement_period`, `opening_balance`, `closing_balance`, `total_debits`,
`total_credits` (amounts are `int`), and `transactions` — a list of 5–12 entries, each

`id_type` (`"Aadhaar Card"` or `"PAN Card"`), `holder_name`, `date_of_birth`, `gender`,
`address`, `issue_date`, `id_number` (masked), `father_name`.

## 4. Image format

| Property | Value |
|---|---|
| Format | PNG (lossless), RGB |
| Payslip | 850 × 1050 px |
| Bank statement | 850 × 1100 px |
| ID proof | 850 × 550 px |
| Font | DejaVu Sans (falls back to PIL default) |

Per-type file sizes: see `DATASET.md` §6.

### Synthetic-data labelling

Every rendered image carries **two labels**, applied when the document is rendered
(before any tampering):

1. **Semi-transparent diagonal watermarks** — the text `SYNTHETIC / TEST DATA`.
2. **Red footer banner** — `★  SYNTHETIC / TEST DATA — NOT A REAL DOCUMENT  ★` in
   white text.

Both are baked into the pixel data. A tampering effect may cover part of a watermark,
but the labels are never removed by the generator.

### Tampering

Tampered documents have exactly one of these effects applied to one random rectangle
(`_apply_tampering`): `blur_region` (Gaussian blur), `color_shift` (colour shift),
`noise_patch` (random noise) or `text_overlay` (white box with "ALTERED VALUE").

## 5. The 5 Day 1 payslips — do not overwrite

`data/synthetic/payslip_001.png` … `payslip_005.png` are the original Day 1 test images.
They are **not** part of `index.csv`, and they are **different files** from
`genuine/payslip_001.png` etc. despite the shared names. `tests/test_analyzer.py` reads
them directly, and `tests/test_dataset.py` requires them to exist.

> ⚠️ **Running `python3 scripts/generate_tampered_documents.py` with no flag, or calling
> `generate_payslip_batch()` with its default output directory, overwrites these five
> files without warning.** `generate_payslip_batch()` has no overwrite protection.
> Never point it at `data/synthetic/`.

### Relationship to `data/demo/`

Two Day 1 payslips are also the sources of Founder A's Day 7 demo images:
`data/demo/genuine_payslip_01.png` is a byte-for-byte copy of `payslip_002.png`, and
`data/demo/genuine_payslip_02.png` of `payslip_003.png` (recorded in
`data/demo/demo_manifest.json`). Overwriting the Day 1 payslips would also break that
recorded provenance.

The indexed dataset stays at **75** documents. The Day 1 payslips are outside the index,
and the images in `data/demo/` are demo copies or derivatives, **not** additional indexed
documents — do not add them to `index.csv` or count them in dataset statistics.

## 6. Generator modes — what is safe

`scripts/generate_tampered_documents.py` behaviour, verified on Day 7:

| Command | What it does | Safe on the current repository? |
|---|---|---|
| `python3 scripts/generate_tampered_documents.py` (no flag) | Writes 5 payslips to `data/synthetic/payslip_001.png`…`005.png` | **No — overwrites the Day 1 payslips** |
| `… --day2` | Rebuilds documents `001`–`025` with seed 42, then rewrites `index.csv` | **No.** On the current dataset it stops with `FileExistsError` before writing anything, but it is not a supported workflow and on an empty folder it would replace `index.csv` |
| `… --day4` | Appends 50 documents from the next free number with seed 4 and appends rows to `index.csv` | **No.** It does not overwrite files, but re-running it reproduces documents `026`–`075` byte-for-byte under new numbers (`076`+), creating duplicate content, and it breaks `tests/test_dataset.py` counts |

**Do not run any generator mode against `data/synthetic/`.** The indexed dataset is final
for this sprint.

### Safe workflow: generating documents for experiments

Write to a separate directory **outside** `data/synthetic/` and choose a seed that has not
been used (not 42 or 4):

```python
import random
from pathlib import Path
from faker import Faker
from scripts.generate_tampered_documents import generate_full_dataset, write_index_csv

out = Path("/tmp/docfraud_experiment")          # anywhere outside data/synthetic/
Faker.seed(1001); random.seed(1001)             # new seed → new content
rows = generate_full_dataset(output_dir=out, payslip_count=5,
                             bank_stmt_count=5, id_proof_count=5)
write_index_csv(rows, out)                      # writes out/index.csv only
```

`generate_full_dataset()` refuses to overwrite an existing document
(`FileExistsError`), and `write_index_csv()` writes `index.csv` inside the given
directory only. Run this from the repository root.

### Inspecting a single record (no files written)

```python
from scripts.generate_tampered_documents import (
    generate_fake_payslip, render_payslip_image,
)

record = generate_fake_payslip()      # dict, see §3
image = render_payslip_image(record)  # PIL.Image in memory; save it outside data/synthetic/
```

### Extending the official dataset

This changes the validated dataset and must be a deliberate, reviewed change:
generate with a **new** seed, `start_index` set to the next free number, append rows with
`append_index_csv()` (which rejects duplicate filenames), update the expected counts in
`tests/test_dataset.py`, re-run `scripts/dataset_stats.py`, and update `DATASET.md`.

## 7. Reproducibility

The CLI modes seed Faker and `random` before generating (`--day2`: 42, `--day4`: 4), so the
same mode always produces the same images. That is also why re-running a mode duplicates
existing content. Use a new seed for new content.
