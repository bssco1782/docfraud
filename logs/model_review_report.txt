Optimisation applied on Day 9 (outputs unchanged):
- ModelAPI.load_model sets the forest to n_jobs=1: one document per call, so joblib thread start-up only added latency and competed with the MAX_CONCURRENT_ANALYSES request slots.
- ModelAPI.predict makes one forest pass (predict_proba) and takes the argmax as the class, exactly as RandomForestClassifier.predict does, instead of calling predict and predict_proba.
- Typical page end-to-end: 297 ms -> 136 ms (2.2x faster). Scores, confidences and interpretations were compared before and after on 175 files (164 held-out, 5 demo, 6 fixtures): identical.

RECOMMENDATIONS FOR FUTURE VERSIONS
--------------------------------
- Robustness first: the largest risk for real uploads is degraded input (jpeg_q85, downscale_75, downscale_50, down_up_50, rotate_90, rotate_180, skew_1deg, skew_3deg, crop_2px lose more than 10 points). Train with those degradations for both classes and normalise pages (deskew, auto-rotate, trim borders, fixed resolution) before feature extraction.
- Model size: n_estimators=200 reaches CV accuracy 0.924 (deployed 0.924) at 3.63 MB (deployed 5.45 MB). A smaller forest is an option for v3; choose it by CV on training data and confirm on a NEW holdout set.
- Save future models with n_jobs=1 (single-document inference) so any loader gets the fast path; ModelAPI now enforces it at load time.
- After the Day-9 change, feature extraction dominates: 113 of 136 ms on a typical page, with the colour (47 ms) and ink (32 ms) groups the most expensive. On a 4000x5000 JPEG, decoding and downscaling take 464 of 1055 ms: decode JPEGs at reduced size (Pillow draft mode) before the 2000-px downscale.
- Calibrate scores (isotonic / Platt on validation data) and add a 'needs review' band around the threshold; report calibrated risk to users instead of raw vote fractions.
- Return the anomalous region in flagged_regions (the features already locate it).
- Validate on real, consented documents before any production decision; every figure here is synthetic.
- Pin package versions and record the model SHA-256 per release; re-run the Day 8 and Day 9 scripts after any change.
