--------------------------------------------------------------------------------
1. WHAT CHANGED SINCE v1
--------------------------------------------------------------------------------
Features
  - 29 local tamper features (core/tamper_features.py) replace the 22 whole-page
    features. Each measures the largest region of the page whose noise, paper
    colour, sharpness or ink darkness differs from the rest of the same page,
    plus a page-level processing fingerprint. v1's page averages barely moved
    when a small rectangle was edited, which capped it at 60%.
Training data
  - 60 frozen TRAIN images + 150 generated DEV documents (seed 7001), each with
    3 processed copies (JPEG q60-95, resize 0.85-1.15x, brightness / contrast
    +/-7%) applied to both classes at the same rate: 840 rows.
  - The frozen TEST set and the generated HOLDOUT set are excluded; the SHA-256
    of every training file is recorded in the model metadata and checked.
Model
  - RandomForestClassifier, 300 trees, class_weight=balanced, random_state=42.
  - Retraining with scripts/train_tamper_model.py reproduces the file's
    probabilities exactly (logs/model_stability_report.txt section 7).
Serving (Day 9, no change to outputs)
  - ModelAPI runs the forest single-threaded (n_jobs=1) and makes one
    predict_proba pass per document. Typical page: 297 ms -> 136 ms. Scores,
    confidences and interpretations are identical on 175 checked files.
  - The /verify interpretation no longer appends a hotspot count (a v1-only
    feature). The response fields are unchanged.

3. FEATURE IMPORTANCE (training data only)
--------------------------------------------------------------------------------
  - Colour, noise and ink carry the model: retrained without each family,
    CV accuracy drops 7.6, 7.1 and 5.2 points. Softness: 1.0 point.
  - The fingerprint family (4 features) and 5 single features (noise_floor,
    soft_blob_s1_0, soft_total_s1_0 and two colour fill ratios) add nothing
    measurable. They are candidates to remove in v3, to be confirmed by CV.
  - The ink family helps on pristine files but not on re-saved copies.

--------------------------------------------------------------------------------
6. KNOWN LIMITATIONS
--------------------------------------------------------------------------------
  - Synthetic data from one generator only (three templates, four edit types).
    Accuracy on real payslips, statements and ID cards is unknown.
  - Degraded inputs (section 4). Phone photos, scans, rotated or cropped pages
    are outside the validated range, but the API still returns a score for them.
  - Non-document images (photos, blank pages) score 0.55-0.62 and are reported as
    tampered. There is no "not a document" output.
  - Scores are uncalibrated RandomForest vote fractions, not fraud probabilities.
  - flagged_regions (added after release, section 10) marks anomalies, not proof;
    it misses about half of the text overlays.
  - Only the first page of a PDF is analysed.
  - The frozen TEST and HOLDOUT sets have been used for v2's evaluation and for
    the Day 9 robustness tests. A new model needs a new holdout set.

7. FAILURE CASES
--------------------------------------------------------------------------------
  False positives (3, all bank statements): genuine/bank_stmt_059.png 0.58,
    genuine/bank_stmt_053.png 0.50 (exactly on the threshold),
    genuine/bank_stmt_2084.png 0.59.
  False negatives (10, all HOLDOUT):
    - 3 blur edits on blank paper that changed no pixel (undetectable);
    - 2 white-on-white text overlays that left only the inserted words;
    - 5 visible edits missed: 2 colour shifts on payslips and 3 text overlays
      on bank statements.
  Demo: tampered_payslip_02.png (0.15) uses a text-replacement edit that v2 was
    not trained on.
  Fragile documents: some bank statements change label under 8-9 of the 13
    degradations (logs/model_robustness_report.txt).

8. UPGRADE AND ROLLBACK
--------------------------------------------------------------------------------
  - The default MODEL_PATH (data/models/fraud_model.pkl) serves v2; no
    configuration change is needed.
  - Rollback: set MODEL_PATH=data/models/fraud_model_v1.pkl and restart. ModelAPI
    selects the v1 extractor from that file's schema.
  - After any retraining: python scripts/prepare_demo_dataset.py --rescore, then
    run scripts/model_validation.py, model_stability_test.py,
    feature_importance.py, model_robustness_test.py and model_review.py.
  - Requirements: scikit-learn 1.9.1, numpy 2.4.6, SciPy, OpenCV 5.0.0.93 and
    Pillow 12.3.0 were used. requirements.txt pins scikit-learn==1.9.1 (Day 10),
    because the pickled model depends on it; pin the others before deployment.

--------------------------------------------------------------------------------
9. FUTURE IMPROVEMENTS (v3)
--------------------------------------------------------------------------------
  1. Robustness: add rotation, skew, border crops, downscaling and light blur to
     the processed training copies (both classes). Normalise pages first
     (auto-rotate, deskew, trim borders, fixed resolution). Choose by CV on
     training data, then evaluate once on a NEW holdout set.
  2. Real documents: collect a labelled, consented set of real documents and
     measure before any production decision.
  3. Out-of-scope input: detect non-documents and unsupported inputs and reject
     or flag them.
  4. Calibration: isotonic or Platt scaling on validation data, plus a "needs
     review" band around the threshold.
  5. Localisation: done (section 10). Next: text overlays whose ink matches the
     page, and resolution-independent tile thresholds.
  6. Simplification: drop the features that add nothing (section 3). 200 trees
     match 300 in CV at 3.6 MB instead of 5.5 MB. Save with n_jobs=1.
  7. Speed: decode large JPEGs at reduced size (Pillow draft mode); for typical
     pages, the colour and ink feature groups are the main cost.
  8. Bank statements: the weakest document type, both clean and degraded.

10. POST-RELEASE UPDATE: flagged_regions (localisation)
--------------------------------------------------------------------------------
Same model file and SHA-256; features, scores and verdicts are unchanged.
  - /verify returns flagged_regions for model v2: boxes with x, y, width, height
    (pixels of the uploaded image; PDF: page 1 at 200 DPI), area and type
    (noise, colour, softness, ink, or several joined by '+' when boxes merge).
    Largest first, at most 5.
  - Regions are returned only when tamper_risk_score >= TAMPER_THRESHOLD, so they
    agree with the verdict. The interpretation then adds "N suspicious region(s)
    located (see flagged_regions)." Model v1 (rollback) still returns [].
  - Source: the tile masks behind the features (core/tamper_features.py,
    extract_with_regions; minimum region sizes in LOCATE_MASKS chosen on DEV only).
    extract_tamper_features gives identical values; cost about 3 ms per page.
  - Accuracy (scripts/localization_eval.py -> logs/localization_report.txt; a hit
    is a box intersecting the true edit rectangle, recovered by replaying the
    generator; edits that changed no pixel excluded):
                          hit             top-1    box precision  genuine w/ boxes
      DEV (design set)    49/59 (83.1%)   49/59    54/54          0/87
      Held-out            55/67 (82.1%)   52/67    61/69          2/93
    Held-out by method: noise patch 28/28, blur 7/7, colour shift 10/13,
    text overlay 10/19 (7 misses on bank statements, where the inserted words
    share the page's ink darkness).
  - Limitation: like the score, boxes assume the training resolution. On DEV
    pages resampled to 0.75x, 1.5x or 2.5x, every genuine page gets locator boxes
    (new anti-aliased colours and noise), and the model flags 4, 55 and 86 of 87.
  - data/demo/demo_manifest.json keeps the interpretation recorded on Day 8; the
    live text for tampered_payslip_01.png now ends with "1 suspicious region(s)
    located (see flagged_regions)." Its box (x=198, y=321, 96 x 9 px, ink) covers
    the replaced account number (recorded edit [197, 321, 55, 12]).
