1. FEATURES COMPLETED
--------------------------------------------------------------------------------
API (backend/)
  - GET  /health  public readiness check: {"status": "ok", "version": "0.1.0"}
  - POST /verify  multipart upload -> tamper_risk_score, confidence,
                  flagged_regions (always empty), interpretation
  - X-API-Key authentication on protected routes (401 missing, 403 wrong key);
    unknown routes return 404 before authentication is checked
  - Upload validation: .jpg/.jpeg/.png/.pdf only, non-empty, <= MAX_FILE_SIZE
    (10 MB default, checked from Content-Length and from the bytes read)
  - One JSON error envelope for every error (success, error, code, detail[, details])
    covering 400, 401, 403, 404, 405, 413, 422 and 500
  - Model loaded once at startup (lazy fallback on first request), thread-safe
  - CPU-bound inference offloaded to a worker thread so /health stays responsive
  - All settings in backend/config.py from environment variables: API_KEY,
    MODEL_PATH, MAX_FILE_SIZE, TAMPER_THRESHOLD, CORS_ORIGINS
  - OpenAPI documentation at /docs, /redoc and /openapi.json

Analysis engine (core/)
  - Image loading for PNG/JPEG and PDF (first page rendered at 200 DPI)
  - Error Level Analysis plus noise, blockiness, edge and intensity statistics:
    22 whole-image features
  - Random Forest training, evaluation, model save/load

Data and tooling
  - 75-document synthetic labelled dataset (48 genuine / 27 tampered;
    30 payslips / 23 bank statements / 22 ID proofs) with index.csv
  - Frozen 60/15 train/test split; 5-image demo set with manifest
  - Scripts: dataset generation and statistics, training, final validation,
    demo preparation, load testing, API test report generation

Quality
  - 256 automated tests: 253 passed, 2 skipped, 1 xfailed, 0 failed
  - tests/test_api_comprehensive.py: 31 API tests, < 1 s, 82% line coverage of
    backend/ from that module alone
  - ruff lint configuration (ruff.toml); `ruff check .` passes
  - Documentation: README, API_DOCS, ARCHITECTURE, DEPLOYMENT, DATASET,
    DATA_FORMAT_NOTES, PROGRESS

--------------------------------------------------------------------------------
4. KNOWN LIMITATIONS
--------------------------------------------------------------------------------
  - Trained and evaluated on synthetic documents only; real-world accuracy unknown.
  - 60% held-out accuracy with a 50% false-positive rate: not usable for
    automated decisions.
  - The deployed fraud_model.pkl was refit on all 75 documents, including the
    15 test images, so it has no clean held-out measurement of its own.
  - All 22 features are whole-image statistics; small local edits (text
    overlays, patches) are weakly detected.
  - tamper_risk_score is an uncalibrated vote fraction, not a fraud probability.
  - flagged_regions is always empty; the API cannot show where an edit is.
  - The `threshold` query parameter is accepted and validated but ignored.
  - Only the first page of a PDF is analysed.
  - ~5 documents/s per process; multi-worker and networked performance untested.
  - Security: single shared API key compared in plain text, insecure default
    key, CORS open by default, no HTTPS, no rate limiting.
  - Dependencies are unpinned; the pickled model depends on compatible
    scikit-learn / numpy versions.
  - Model files are loaded with pickle: only load trusted, repo-produced files.
