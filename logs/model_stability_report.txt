--------------------------------
SUGGESTED IMPROVEMENTS
--------------------------------
- Keep the inference path as it is: it is deterministic (identical output on every call, path, thread and process). Record the SHA-256 of fraud_model.pkl in every release and re-run this script after any dependency upgrade; scikit-learn / numpy / OpenCV / Pillow versions are part of the model.
- Pin the package versions listed above (requirements.txt is unpinned). A different library version is the most likely source of future score drift, and pickle compatibility is not guaranteed across scikit-learn versions.
- Retraining noise: with 300 trees the demo scores move by up to 0.07 between seeds (mean std 0.016); 900 trees gives mean std 0.010. When the model is next retrained, consider n_estimators=900 (choose it by train-only cross-validation, not on the frozen test set or the demo images).
- Report scores near the threshold as 'needs review' instead of a hard genuine/tampered verdict (e.g. a band around TAMPER_THRESHOLD, set from validation data), so near-threshold images are not presented as confident decisions.
- Input sensitivity is a model-quality problem, not a determinism problem. The label flips above come mostly with large shifts in colour_rare_blob_2pct_fill, flat_frac, ink_rare_line, which change when a page is re-saved, resized or re-exposed, so the model partly measures the file's processing history rather than the edit. Measure local anomalies relative to the page's own compression level (estimated JPEG quality, noise floor) and widen the processing applied to training copies.
- Stability says nothing about accuracy: see logs/model_validation_report.txt (held-out accuracy and demo results).
